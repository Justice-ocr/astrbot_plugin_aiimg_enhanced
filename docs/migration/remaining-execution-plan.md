# Web Studio 剩余工作集中实施方案

日期：2026-09-23
状态：R1–R5 本地总验收完成，真实 AstrBot/服务商联调待环境
适用分支：`refactor/unified-web-studio`

本方案接替原分阶段验收方式。已有实现继续保留，剩余核心模块连续完成；在全部实现结束前，不运行验证或检查命令。

## 1. 执行纪律

实施期间只允许：

- 阅读现有代码、方案、接口和数据结构。
- 修改源代码、迁移逻辑、文档和静态资源源码。
- 为实现功能而查询本地仓库内容。
- 记录尚待最终验证的风险和假设。

全部核心模块完成前禁止：

- `pytest`、测试脚本和临时冒烟测试。
- `py_compile`、`compileall`、Astro check、TypeScript 检查和 lint。
- 前端 build、`scripts/build_studio.mjs` 和静态产物扫描。
- 启动开发服务器、浏览器检查、截图或真实 AstrBot 联调。
- 付费模型调用、真实服务商请求和发布操作。
- 用局部检查结果宣布某个阶段已经验收完成。

实现阶段允许保留待验证代码，但不得故意留下已知的空实现、假按钮、静默降级或与方案冲突的临时分支。

`_conf_schema.json` 视为用户本地文件：不修改、不恢复、不暂存、不提交。

## 2. 剩余范围与顺序

按下列顺序连续实施。后续批次可以依赖前一批次的数据结构，但中间不做验证。

### R1：画布任务与项目闭环

目标：画布不仅能摆放素材，还能承载生成任务、恢复任务和稳定保存。

实施项：

1. 扩展画布节点结构，明确区分素材节点和生成节点。
2. 生成节点保存 `job_id`、服务商、模式、提示词、尺寸、分辨率、参考素材和参数快照。
3. 提交前先保存项目；生成请求绑定 `project_id` 和节点 ID。
4. 刷新或重新打开项目时只查询已有 `job_id`，绝不自动重新提交。
5. 生成完成后将受管素材 ID 写回节点；失败、取消和中断状态保留在节点上。
6. 删除画布节点不删除任务记录或上游任务。
7. 实现节点连线的创建、删除和持久化，限制非法自连接和重复边。
8. undo/redo 只处理节点、连线和视图编辑，不触发或撤销付费任务。
9. 每个节点展示服务商与关键参数快照。
10. 完成画布项目 ZIP 导出，清单只引用当前会话的受管素材。
11. 处理项目冲突、另存副本、切换会话和异步响应过期。

完成边界：画布项目的数据结构和交互代码齐全，代码中不存在依赖全局最近 50 条任务才能恢复项目的逻辑。

### R2：Agent 规划、会话与受限执行

目标：Agent 是可恢复、可审阅、受约束的任务规划器，而不是批量生成表单。

实施项：

1. 新增持久化 Agent 项目或会话文档，保存用户目标、规划结果、消息、确认记录和关联任务。
2. Agent 模型只获得结构化的受限能力描述，不获得 API Key、文件系统、shell、配置写入或任意 URL 请求能力。
3. 规划输出采用严格结构：任务类型、提示词、服务商、参数、参考素材、数量和依赖关系。
4. 后端验证规划中的服务商能力、参数范围、会话素材归属和最大任务数量。
5. 审阅页展示最终任务列表、服务商、数量、参数和费用是否可知。
6. 确认凭据绑定规范化规划、服务商配置、数量、会话、有效期和幂等键。
7. 执行时使用确认过的不可变计划快照，不允许模型在确认后增量添加任务或更换服务商。
8. 每个子任务使用独立且可恢复的幂等键；失败不自动无限重试。
9. Agent 会话重新打开后恢复规划和任务状态，不重新请求模型或重新提交生成。
10. 取消 Agent 只取消尚未提交的本地步骤；已提交上游任务按真实能力展示状态。

完成边界：Agent 规划、确认、执行和恢复均由后端持久记录驱动，前端刷新不会改变计划语义。

### R3：GIF 生成帧与浏览器编码

目标：GIF 项目覆盖帧生成、调帧、恢复、导出和受管结果。

实施项：

1. GIF 帧允许绑定现有素材或统一图片生成任务。
2. 生成帧保存 `job_id`，恢复规则与画布相同，不自动重复付费提交。
3. 保留重复素材帧、逐帧时长、排序、循环次数和输出尺寸。
4. 增加专用 Web Worker 编码，避免编码阻塞主线程。
5. Worker 前检查 60 帧、最长边 1024 和输入总量 100MB。
6. 编码进度、中断和错误进入明确 UI 状态；中断只终止本地编码。
7. 编码结果上传为当前会话的受管 GIF 素材。
8. 保留服务端编码作为兼容回退，但不能与浏览器编码产生重复输出。
9. 支持下载、进入素材库和可用时发送到聊天；发送失败不重新生成。
10. 项目重新打开后恢复帧、时长、任务和最后导出素材。

完成边界：GIF 从帧来源到最终受管素材形成完整链路，主线程不承担编码循环。

### R4：设计、修补、网页复刻与素材嵌入

目标：设计工作区完成切图、模型修补和隔离网页预览。

实施项：

1. 切图项目保存原图尺寸、浮点坐标、网格或自由切片区域和版本。
2. 切片输出登记为受管素材，并可回到设计或画布继续编辑。
3. 修补请求复用统一 edit job，保存遮罩、参考素材、服务商和参数快照。
4. 历史图片在首次使用时转为受管素材，同一编辑会话不重复复制。
5. 网页模型生成只返回静态文件清单，结果先进入编辑区，用户保存后才形成项目版本。
6. 将项目引用的图片素材安全转换为预览可用资源；不暴露本地路径和插件 API。
7. 静态预览继续使用无权限 sandbox iframe、预置 CSP 和允许列表重建文档。
8. 预览禁止脚本、外网、表单提交、同源权限和顶层导航。
9. ZIP 导出规范化路径，只写文件清单和受管素材，不读取客户端任意路径。
10. 历史版本可载入编辑区、另存副本或保存为新修订，不静默覆盖。

完成边界：设计区的切图、修补、网页生成、预览、版本和导出都有实际数据流，不存在仅展示按钮。

### R5：设置迁移、发布开关与兼容收尾

目标：新 Studio 不丢失旧插件功能，且可以安全启用和回退。

实施项：

1. 对照 `feature-inventory.md` 逐项映射旧设置、命令、LLM 工具、服务商和平台行为。
2. 新旧页面共享现有原子保存与 revision 冲突处理，不建立第二套配置源。
3. 服务商普通字段、未知字段和秘密字段分别处理；秘密只显示配置状态。
4. 删除或重命名被功能链引用的服务商时给出明确冲突，不留下悬空引用。
5. 会话人设与全局默认保持独立，参考图职责、顺序和删除回退保持兼容。
6. 旧预设格式继续可读；无法无损解析的格式禁止覆盖保存。
7. 新增 Studio 启用、默认入口和回退逻辑时避开 `_conf_schema.json`，通过现有配置容错读取默认值。
8. 保留旧 Settings 页面和聊天命令；关闭 Studio 后旧入口仍可工作。
9. 增加缺失的发布完整性脚本，检查源代码与默认入口 `pages/Settings` 构建产物一致性。
10. 更新版本、CHANGELOG、第三方来源清单、迁移记录和明确的未验证项。

完成边界：功能清单每一行都能指向保留入口或 Studio 实现，不存在因新页面而删除的旧能力。

- 不写“验收通过”“构建通过”或“发布就绪”。

## 4. 最终统一验证

只有 R1 至 R5 全部达到“代码完成待总验收”后，才进入本节。

### 4.1 静态与自动化检查

按顺序只执行一次：

1. Python 编译检查。
2. 受影响的现有高风险测试：会话隔离、幂等、防重复付费、项目引用、视频恢复和媒体路径安全。
3. 前端依赖锁一致性检查。
4. Astro/TypeScript check。
5. lint；若项目尚无可执行 lint 配置，则明确记录而不临时引入新体系。
6. 前端生产 build。
7. 原子安装到 `pages/Settings`。
8. 发布完整性脚本与敏感信息扫描。
9. `git diff --check` 和最终工作区审计。

不新增覆盖率门槛、不建立大型测试矩阵、不为低风险 UI 细节补大量测试。

### 4.2 一次浏览器验收

只检查桌面和手机两个代表视口，走一条贯穿流程：

1. 选择会话和独立人设。
2. 创建图片任务并在任务中心观察状态。
3. 把结果加入画布，保存后刷新恢复。
4. 从画布或素材进入 GIF，调序并导出。
5. 运行一次提示词处理和 Agent 审阅；没有授权时不执行付费任务。
6. 切图、保存设计项目并打开隔离网页预览。
7. 检查旧 Settings 入口仍可访问。
8. 检查无横向溢出、遮挡、空白媒体和明显控制错位。

### 4.3 安全与恢复验收

使用少量针对性输入检查：

- 跨会话读取素材、项目、任务和人设被拒绝。
- 相同幂等键不能因刷新产生第二次生成。
- Agent 确认后修改数量、服务商或参数会失效。
- 恶意 HTML 无法执行脚本、请求插件接口或跳转顶层页面。
- ZIP 路径穿越、绝对路径和驱动器路径被拒绝。
- 中断的视频和画布/GIF 任务只恢复查询，不重新提交。
- 历史图片超过 100 张清理后，已转存或被项目引用的素材仍可用。

### 4.4 真实运行检查

- 在可用的测试 AstrBot 中检查 Studio API 路由和页面桥接。
- 未经用户明确授权，不发起任何付费图片或视频生成。
- 没有凭据的服务商标记为“未实测”，不能用模拟结果宣称真实可用。

## 5. 最终修复规则

统一验证发现问题后：

1. 汇总问题并按数据安全、重复计费、功能阻断、UI 问题排序。
2. 集中修复，不在每个修复后重复全套检查。
3. 修复全部完成后，仅重跑受影响检查和最终 build/install。
4. 最终记录真实通过项、未测项和残余风险。

## 6. 最终完成标准

以下条件必须同时满足，才能宣布整体完成：

- R1 至 R5 全部实现。
- 最终统一验证没有未处理的阻断问题。
- 新旧入口、聊天工具、服务商、人设、历史和任务行为均有保留证据。
- 项目刷新不自动重复提交付费任务。
- Web 前端不持有服务商 Key，也不直接请求商家接口。
- Studio 构建产物与源码一致。
- 版本、CHANGELOG、许可和迁移文档已更新。
- `_conf_schema.json` 的用户本地修改保持原样且未进入提交范围。
